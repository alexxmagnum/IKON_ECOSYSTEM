# 05_INFORMATION_ARCHITECTURE

## Objetivo

Definir todos los tipos de usuarios que utilizarán IKON.

Este documento sirve para comprender las necesidades reales de cada persona.

No todos los usuarios utilizan IKON de la misma manera.

Cada uno persigue objetivos distintos.

El producto deberá adaptarse a ellos.

---

# Introducción

IKON no tiene un único usuario.

Tiene varios perfiles.

Cada uno necesita herramientas diferentes.

La experiencia deberá personalizarse según el contexto.

---

# Usuario 1

## Visitante

No es socio.

Puede llegar por:

* Google.
* Instagram.
* TikTok.
* Recomendación.
* QR.
* Amigos.

Objetivos:

* conocer el club,
* reservar,
* consultar la carta,
* ver eventos,
* descubrir actividades.

---

# Usuario 2

## Cliente ocasional

Ha venido alguna vez.

Conoce parcialmente el club.

Objetivos:

* reservar rápidamente,
* repetir experiencias,
* descubrir novedades,
* volver con mayor frecuencia.

---

# Usuario 3

## Socio

Es el usuario más importante.

Visita IKON con frecuencia.

Objetivos:

* jugar,
* reservar,
* participar,
* crear experiencias,
* relacionarse,
* competir,
* descubrir actividades.

---

# Usuario 4

## Organizador

Puede crear:

* partidas,
* encuentros,
* grupos,
* cenas,
* retos,
* actividades.

No pertenece necesariamente al personal del club.

---

# Usuario 5

## Staff

Trabajadores.

Restaurante.

Recepción.

Golf.

Administración.

Objetivos:

* ayudar usuarios,
* gestionar incidencias,
* mantener actividad.

---

# Usuario 6

## Manager

Gestiona el funcionamiento del club.

Objetivos:

* aumentar actividad,
* aumentar ocupación,
* mejorar ventas,
* analizar datos,
* organizar eventos.

---

# Usuario 7

## Administrador

Control total del sistema.

Configuración.

Usuarios.

Permisos.

Contenido.

Automatizaciones.

---

# El verdadero protagonista

Aunque existan muchos perfiles,

el protagonista del producto será siempre:

La persona que quiere vivir una experiencia.

Nunca el administrador.

Nunca el software.

Nunca la tecnología.

---

# Regla

Cada nueva funcionalidad deberá indicar claramente:

¿Para qué tipo de usuario existe?

Si no existe una respuesta clara,

la funcionalidad todavía no está suficientemente definida.
